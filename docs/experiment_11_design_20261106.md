# 実験11の検討案：D 条件づけ比較のモデル横断移植

**状態：提案。未凍結・未実装・未生成・未採点。2026-11-06。**

この文書は、[実験10の設計メモ](experiment_10_design_20261103.md)の D 条件づけ比較を
**別の対象モデル**へ移植する案の検討記録である。実験10自体はまだ未凍結・未実行であり、
この文書はその後継試験としての順序と差分を整理するものであって、予測固定・事前登録・
結果のいずれでもない。

## 動機と問い

実験9までの全証拠は `HuggingFaceTB/SmolLM2-360M-Instruct` 単独の出力に基づく。
予測比較の結論が「この360Mモデルのこの設問群での癖」なのか、
「証拠構造と指示条件に共通な応答分布の性質」なのかは、現行データだけでは分離できない。

> 実験10と同じ予測器・同じ主比較・同じ新規評価問題群を、
> 別モデル（`meta-llama/Llama-3.2-3B-Instruct`）の独自の開発・評価生成で実施したとき、
> 主比較の符号と大きさは同じ向きになるか。

これは「Aモデルで見た傾向の再現試験」であり、モデル間の因果比較や
ペルソナの有無の判定ではない。対象モデルが違えば応答分布そのものが違うため、
**同じ結論が出ても「同じ機構」とは言わない**。

## 重要な設計上の事実：開発データは移植できない

実験10の開発624生成・評価576生成は **SmolLM2 自身の生成物**である。
予測器は対象モデル自身の応答コード分布を fit するので、Llama 版には
Llama 自身の開発生成が必要になる。SmolLM2 の出力を Llama の開発として使ったり、
混ぜたりしない。これは件数倍増を意味し、移植の最大のコストである。

| プール | SmolLM2 版（実験10案） | Llama 版（本案） |
|---|---|---|
| 開発 | 既存 v9 開発336 + 旧評価288（開発へ再割当） | **新規に開発用生成が必要** |
| 評価 | 新題48 × 6条件 × 2反復 = 576 | **同じ新題48題**、同6条件、2反復 = 576 |

新題は両モデルで共通にする案。題材が共通なら「題材差」は主比較の符号比較から
除ける。ただし同一題への応答分布がモデル間で異なること自体は結果であり、
交絡ではない。

Llama 版の開発生成は、**既存の実験8/9の問題を開発専用の既知題として Llama で
再生成する方針を 2026-11-06 に選択した**。題材執筆コストがかからず、v9 開発と
同じ設問構造（28題×6条件×2反復=336、加えて旧評価24題×6×2=288の計624を
目安）を保てる。**同じ題材を開発と評価の両方で使い回すことはしない**——
開発用の既知題と評価用の新題48題は完全に分ける。既知題の選択・fold 表は
凍結時に件数とともに固定する。

## 同一性の境界：何を揃え、何が本質的に違うか

揃えるもの：

- 予測器4候補（Global / Evidence / Setting / Joint）、縮約式、rho 候補、同点規則
- 主比較 Joint−Evidence、D の二値 Brier、判定規則、進行閾値の形
- rubric、観察の A/B 分離、盲検手順
- 評価題48題、6指示条件、反復数、seed 導出規則の形
- `pobs` runner、plan/lock/scoring の整合機構

本質的に違うもの（交絡として除去できず、記録する）：

- モデル重み・モデル ID・revision・全ファイルハッシュ
- tokenizer・chat template・EOS 集合・語彙
- **dtype**：Llama-3.2-3B は bf16 ネイティブ。float32 再キャストは別の重みを
  作る行為なので、主試験は `bfloat16` とする案。SmolLM2 の float32 との差は
  精度差であり「モデル差」の一部として扱い、分離主張はしない
- デバイス：実験10案は portable CPU float32、本案は furnace CUDA。
  backend 差とモデル差を分離したければ、SmolLM2-CUDA や Llama-CPU の
  補助 run が必要になる（下記）

### backend/モデル/精度の分解オプション

| run | モデル | backend | dtype | 位置づけ |
|---|---|---|---|---|
| E10 | SmolLM2-360M | CPU | float32 | 主試験（実験10） |
| E11 | Llama-3.2-3B | CUDA | bfloat16 | モデル移植主試験（本案） |
| 補助A | SmolLM2-360M | CUDA | float32 | backend 差の較正 |
| 補助B | Llama-3.2-3B | CPU | bfloat16 | backend 差の較正（遅い） |

補助 run を行う場合も、主比較の判定には使わず記述報告に留める。
同じ seed が同じ出力を保証しないことは runner の設計どおりである。

## この試験で答えられないこと

- 「Llama にはペルソナがあるか」— D の予測可能性は人格の証明ではない
- モデル間の性能差の原因（重み、指示 tuning、tokenizer、精度のどれか）の帰属
- SmolLM2 での失敗/成功が一般モデルに拡張できるかの完全な答え——
  3B instruct 一点の追加では「モデル一般」には届かない。第3モデルへの移植は
  また別の計画とする
