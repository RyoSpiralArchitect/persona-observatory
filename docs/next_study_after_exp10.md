## 2. Settingを基準に、成分の縮小を開発側だけで選ぶ

計算部の草案は `src/persona_observatory/component_predictors.py`。
これは合成カウントで検査する工学的候補で、科学的protocolの凍結でも実データのfitでもない。
旧 `predictors.py` と凍結済み予測は変更しない。

開発カウントのD数をd、件数をnとする。候補は次で定義する。

- 全体 `g = (d + 0.5) / (n + 1)`。
- Setting基準 `p_s = (d_s/n_s + g)/2`。この草案ではrho=1を固定する。
- evidenceの変化量 `b_e = logit((d_e+0.5)/(n_e+1)) - logit(g)`。
- Settingへ縮めたcell率 `p_se = (d_se + 16*p_s)/(n_se+16)`。
- cell残差 `r_se = logit(p_se) - logit(p_s) - b_e`。
- 最終gate `sigmoid(logit(p_s) + λ_e*b_e + λ_i*r_se)`。

`0 <= λ_i <= λ_e <= 1` として、相互作用を主効果以上に残さない。
候補は `{0, 0.25, 0.5, 1}` からの10組。両方0ならSettingと一致し、両方1ならp_se。
未知のSettingはg、未知のevidenceは変化量0、未知のcellは残差0へ戻す。
4カテゴリの条件付き構成は、他の比較と同じ全体プールを使う。
これはlogit上の周辺差とcell残差であり、旧研究の線形ANOVA成分や因果効果と同一ではない。

校正後に、ラベルの版・開発データの役割・この式と候補集合を確定する。
質問とその言い換え・同一シナリオを同じfoldに保ち、全条件・反復をまとめてholdoutする。
平均は質問を等重み、その後A/Bを等重みとし、A/Bのfitは別々に保つ。
候補選択は開発CVだけで行い、同点は小さいλ_i、次に小さいλ_eを選ぶ。
CV値は選択のための数値であり、独立した改善の証拠にはしない。
このCV選択・fresh予測の発行部分は、人手校正の完了後に実装・凍結する。

## 3. 開発質問を広げてから、新規評価を別に凍結する

次の設計はまだ草案。旧質問をfreshに改称しない。v10を利用するなら明記してdevelopmentへ移す。
主に「What can be concluded ...」へ揃えた旧質問から、以下の軸を交差させる。

- 問いの対象：効果の有無、証拠の十分性、条件付き比較、判断保留を含む意思決定。
- 問いの形：直接質問、簡潔な問い、複数文脈の問い。答え方を直接指定する指示とは区別する。
- 証拠：既存4strataを維持し、領域や問い型と交絡させない。
- 内容：開発と評価でシナリオ、具体物、因果関係の組合せを分ける。ID一致検査に加えて人手で重複を見る。

予算案は開発96問×6設定×2反復=1,152出力、新規評価192問×6設定×2反復=2,304出力。
これは開始命令でも凍結済み予算でもない。ラベル付けの負担と未解決率を校正後に見直す。
同じSmolLM2-360M-Instructの固定重み、MPS実行条件を記録し、MLX一致は別の工学検査とする。
推論バックエンドと問いの多様化を同時に変更した比較から、単一要因の効果は主張しない。

一次比較案は新候補−SettingのD Brier。新しい効果量閾値・NLLと全体基準のguard・
不確実ラベルの扱い・停止条件を、開発後かつ新規評価の生成前に一つのprotocolへ固定する。
同じ評価結果を見て候補・閾値・除外を変えない。未達なら限定的な負の結果として閉じる。
未解決の帰属を無理に一意化して「成功」にしない。
