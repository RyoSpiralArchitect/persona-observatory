## 問い

> 指示条件を知ることで、証拠の種類だけからは得られない直接判断の予測情報が増えるか。

判断内訳はすべての候補で同じ全体分布に固定し、D の確率のプール先だけを比較する。

| 候補 | D の確率に使う区分 |
|---|---|
| Global | 全体 |
| Evidence | 証拠の種類 |
| Setting | 既知の指示条件 |
| Joint | 指示条件 × 証拠の種類 |

この四つのモデルは、まだこのリポジトリの portable CLI では学習・選択していない。
生成 runner を用意したことと、予測試験の実装・実施を区別する。

## 先に確定すること

1. 新しい評価問題群、指示条件、生成数、seed の生成規則を確定する。
2. 開発データの出自と役割を明記する。過去の評価データを使う場合は、
   今回から開発用に移したことを明記し、新しい評価に再利用しない。
3. 全候補で同じ開発集合を使う。質問を単位として分割し、同じ質問の
   指示条件・反復をまとめて同じ fold に置く。
4. 全体率、全体の判断内訳、縮約の強さを各 fold の訓練部分だけで推定する。
   縮約の候補と同点処理も結果を見る前に決める。
5. D の二値 Brier を主指標にする案を確定し、比較対象と成功基準を書く。
   NLL、5分類損失、問題単位の差、観察者間の違いは補助項目として固定する。
6. 全候補の選択結果と全評価点への予測を保存し、入力・コード・確率の
   ハッシュを固定してから新しい生成を開始する。

主比較の候補は、Joint−Evidence と Joint−Setting。
これを共同主基準にするか、優先順位を付けるか、差の大きさをどう扱うかは
新規生成前に確定する。実験9の結果を見て、この案の成功条件を満たしたことにはしない。

## 縮約の形

グループ $c$ に開発出力が $n_c > 0$ 件、直接判断が $d_c$ 件あり、
訓練部分全体から求めた基準率を $g_D$ とすると、一つの候補形は

$$
\hat r_c = \frac{d_c + \rho n_c g_D}{n_c + \rho n_c}.
$$

これは実験9と同じ強さのパラメータ化で、`rho = inf` は全体率に戻す極限。
空のグループの扱い、平滑化、候補集合、最終 fitting の方法を実装時に固定する。
候補式を文書に書いた段階では、予測固定済みとは呼ばない。

## Mac と furnace を比較するとき

まず一つの backend で研究上の主比較を固定する。
別 backend の実行は、その後の再現・移植性の試験として分ける。
モデル重み、tokenizer、chat template、質問、指示、seed が同じでも、
精度形式や演算による生成差が残る可能性がある。

新しいモデルへ移す場合は、モデル差と backend 差を分けて比較できるようにする。
一つの小型モデルの成績を、モデル一般の性質として扱わない。

## この比較で答えられる範囲

プール先が変わると、一つの推定に使える件数も変わる。
比較で得られるのは、条件情報と推定の安定性を合わせた予測上の価値である。
人格指示の純粋な因果効果や、内部状態の機構をこの比較だけで識別しない。

既知文面への条件づけが有利であった後には、未知の言い回し、異なる問題群、
別モデルへ移す試験が考えられる。その順番と評価単位も、各試験の開始前に決める。
