# 実験10の検討案：証拠種類に指示条件を加える予測価値

**状態：提案。未凍結・未実装・未生成・未採点。2026-11-03。**

この文書は [従来の次回案](next_experiment.md)を具体化した設計メモである。
実験9の記録や判定を変更しない。問題群、開発入力、実装、観察者、実行環境が
揃った時点で別の protocol と機械可読 lock を作る。この文書だけを予測固定や
事前登録と呼ばない。以下の数値と判定規則も、現段階では検討のための提案である。

## 出発点と主張の範囲

実験9の H は、G と F の双方に五分類 Brier で勝つ共同主基準を満たさなかった。
H_gate の最良順位は固定候補内の記述的所見である。H_gate を次の候補にすることは
その結果を見た後の選択なので、確認には新しい問題と生成が必要になる。
根拠は [実験9報告](../research/experiment_09/REPORT_JA.md)と
[元の protocol](../research/experiment_09/PROTOCOL.md)にある。

次は判断の四分類内訳を全候補で共通にし、直接判断 D の確率だけを比べる。
問いは「既知の指示文面を知ることが、証拠種類だけの場合より、新しい題材の
D を予測する助けになるか」。D は指定された回答者による利用可能な判断の有無で、
指示追従や話者帰属も含む。人格の持続、判断の正しさ、内部機構は測定対象にしない。

## 主比較を一つにする提案

| 位置づけ | 比較 | 何を確かめるか |
|---|---|---|
| 主比較 | Joint − Evidence | 証拠種類に指示条件を加える予測価値 |
| 事前指定の補助比較 | Setting − Global | 証拠種類を使わない場合の指示条件の価値 |
| 事前指定の補助比較 | Joint − Setting | 指示条件に証拠種類を加える価値 |
| 全体基準への照合 | Joint − Global、Evidence − Global | 細分化が全体率より有用か |

主指標は **D の二値 Brier**。差は左−右で、負が改善。Joint − Setting は
別の問いなので共同主基準へは入れない。補助比較の成功で主比較の不成立を救済しない。
四候補の全スコアと全比較を、A、B、A/B平均で必ず示す。

この比較は利用できる条件情報と推定の安定性を合わせて測る。
Joint が良くても、指示と証拠の相互作用を識別したとは言わない。
相互作用の主張には、別途固定した加法モデルなどとの比較が必要になる。

## データの役割と上限

| データ | 今回の役割 | 提案する件数 |

| 新作の評価問題群 | 開発・選択に使わない新規評価 | 48題・576生成 |

v9 開発集合との二重計上や反復数の偏りが生じるため、追加しない。
抽出時に元 sample ID、質問 ID、元アーカイブ内パス、ハッシュと今回の役割を残す。
原本を読み取る [件数・ID・ラベル対応の確認](../validation/experiment_10_feasibility_20261103.json)
では、この624生成が重複なく揃い、A/Bのラベルが全IDを覆うことを確認した。
学習用ファイルの抽出・凍結や予測器の fit はまだ行っていない。

新規評価は4証拠層（limited / confounded / supportive / contradictory）各12題、
既知の6指示条件、各2反復。**48 × 6 × 2 = 576生成**、上限96 tokenなので、
最大55,296生成 token。A/B は同じ576生成の1,152観察であり、独立な1,152生成ではない。
48題は観察作業を限定する設計予算で、検出力計算の結果ではない。

新題は v8 の全36題（開発に使わない fit 題も含む）と v9 の24題を合わせた

証拠構造は意図的に共通にする。新しい題材への移植を調べるもので、未知の
指示文面・自然会話一般への移植ではない。新題の執筆・点検には対象モデルを使わない。

## 予測器と選択規則

Global は全体、Evidence は4証拠層、Setting は6指示条件、Joint は24セルで
D の率を推定する。全候補が同じ開発出力を使い、A/B の数え上げは別々にする。
主候補への補正や候補追加は評価生成後に行わない。

訓練部分の生成数を N、D の件数を N_D、直接判断の分類 k の件数を N_k とする。
提案する共通の基準率・判断内訳は次のとおり。

```text
g_D = (N_D + 0.5) / (N + 1)
h_k = (N_k + 0.5) / (N_D + 2)        # k は support/reject/withhold/mixed
r_c = (d_c + rho * n_c * g_D) / (n_c * (1 + rho))
p_k = r_c * h_k
p_no_direct = 1 - r_c
```

Global は r=g_D。空セルと rho=inf は明示的に r=g_D とする。
rho 候補は **0.25、1、4、inf**。Evidence、Setting、Joint ごとに一つの rho を選び、
その候補の全セルと A/B で共通に使う。最小の開発 D Brier を選び、1e-12以内の
同点は強い縮約（inf、4、1、0.25の順）を選ぶ。候補が同一予測へ縮退しても保持する。

この二値平滑化は v9 の「五分類に0.5ずつ加えた後に D を導く」平滑化とは異なる。
全候補に共通で、主目的の二値予測を直接定義するための提案である。
実験9の H_gate と数値的に同一の再現とは呼ばない。平滑化も予測前に固定し、
評価結果を見て v9 式と切り替えない。

開発交差検証は質問ブロックで分ける。同じ質問の全指示条件・反復・観察枝を
同じ fold に置く。原本の4層が各13題であることを確認済みで、各 fold から各層1題を
外す13-foldを提案する。v9の旧 development_fold 0〜6を保ち、旧評価の
topic_index + 7を7〜12へ割り当てる fold 表を上の確認記録に保存した。
ラベルに応じて fold を組み替えない。各 fold の g_D、h、局所件数は訓練部分のみから
求める。各質問内で12生成と A/B を等重みで平均し、質問間も等重みにする。

選択後に全開発集合へ再 fit し、全評価 sample × 2観察枝 × 4候補、計4,608行の
五分類確率を固定する。開発CVの最良値は選択に使った値であり、独立した成功証拠ではない。
最終開発件数は予定どおりなら Joint 各26、Evidence 各156、Setting 各104生成となる。

## 判定と次へ進む条件

質問 q、観察枝 o ごとに、12生成の D Brier の対応差 Joint−Evidence を平均する。
その後48題、最後にA/Bを等重みに平均した値を delta とする。欠けた質問・観察枝を
分母から落として主結果を作らない。完全性確認が通らなければ主判定は `INCOMPLETE`。

**主比較の記述的支持**は delta < −1e-12。これは有限の著者作成問題群における
符号判定であり、有意差や母集団への一般化ではない。A/B別の差と符号、問題単位・
指示条件・証拠層別の差を併記する。

未知の言い回しを使う次段階へ進む基準は、主判定とは別に、以下をすべて要求する案とする。

- delta ≤ −0.005 の絶対 Brier 改善。
- A/B の両枝で Joint−Evidence の D Brier が負（各 < −1e-12）。
- A/B平均で Joint−Global の D Brier が悪化しない（≤ 1e-12）。
- A/B平均で Joint−Evidence の D NLL が悪化しない（≤ 1e-12）。

0.005 は追加の観察費用をかけるための**提案上の実用閾値**で、検出力から
導いた値でも過去の結果が保証する効果量でもない。生成前の議論で確定する。
主比較が負でもこの進行基準に届かなければ「小さい／観察者依存／指標不一致の
改善」としてそのまま閉じ、都合のよい補助指標を主に差し替えない。

主比較が同等・悪化なら、このデータ予算・選択規則・既知文面で追加価値を
支持できなかった、と記録する。条件一般が無意味だとは結論しない。
同じ問いへの出力を増やして成功まで続ける運用はしない。
追加調査は別の開発解析として記録し、新たな評価には別の計画と新題を必要とする。

補助指標は D NLL、五分類 Brier/NLL、観察者のD不一致率、各ブロックの符号数、
1題ずつ除いたときの平均差の範囲とする。除外で良くなっても全題の主判定を変更しない。
判断内訳 h が共通なら、候補間の五分類 NLL 差は D NLL 差に等しいことを検算する。
五分類 Brierには同じ加法恒等式を仮定しない。strict E はDと混同せず、
この試験では新たな予測器選択・成功条件を設けない。

## 生成と観察を混ぜない

対象モデルと revision は既存 manifest の SmolLM2-360M-Instruct を維持する案。
最初の主試験は portable CPU float32、temperature=0.8、top_p=0.95、96新規token、
batch_size=8、cpu_threads=4、既存の6指示文と prompt template を提案する。
ソフトウェア版・chat template・tokenizer・モデル各ファイルのハッシュは実行前に固定する。
`auto` による backend 選択を主試験には使わない。

seed は runner の `seed_namespace | question_id | replicate_id` の SHA-256規則を使う。
namespace は `pobs-exp10-gate-proposed-20261103` を候補とし、凍結時に確定する。
各質問・反復の系列を6条件で共有し、モデルには毎回新しい chat を渡す。
実験9の出力を prompt に挿入しない。MPS/CUDA と別モデルは別の移植試験に分ける。

観察は現行 rubric をハッシュ固定し、二つの分離したコンテキストで全文を意味的に読む。
担当する人／モデル、その版、コンテキスト構築・バッチ分けの方式は未確定である。
現在の設計・結果を読んだコンテキストを、そのまま盲検観察者として流用しない。
条件名・seed・証拠層ラベル・予測・過去の順位・相手のラベルを渡さない。
ただし質問文から証拠構造が読めることまでは遮断できず、盲検の範囲を明記する。

A/B の全ラベルと観察ノートを別々に確定してから採点する。意味ラベルの自動
キーワード代替や、結果を見た後の合議による書き換えはしない。完全一致する
質問・回答者・出力の重複は現行の整合規則に従う。length stop、no_direct、
指示の反復も観測結果として残す。

   `pobs prepare --forecasts` の前後関係に加え、外部 fit の再計算も照合する。
7. 一回だけ生成する。失敗・途中出力を保持し、同じ run の再試行や黙った再開をしない。
8. A/Bを盲検で観察・確定し、採点・原データからの数値検算・全比較の報告を行う。
